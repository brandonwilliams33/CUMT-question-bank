# 矿大 · 课程练习室

面向中国矿业大学同学的学生自建刷题网站，非学校官方平台。纯静态网站，无需后端、数据库、账号或打包工具，适合 GitHub Pages。

## 部署到 GitHub Pages（推荐）

1. 解压交付的 ZIP，进入 `CUMT-question-bank` 文件夹。
2. 在 GitHub 创建一个公开仓库，例如 `CUMT-question-bank`，默认分支使用 `main`。
3. 将文件夹里面的全部内容上传到仓库根目录。根目录必须直接包含 `index.html`，不要把外层 `CUMT-question-bank` 文件夹也套进去。保留 `data/`、`sources/` 和隐藏文件夹 `.github/`。
4. 打开仓库 **Settings → Pages**，在 **Build and deployment → Source** 中选择 **GitHub Actions**。
5. 在 **Actions** 页面打开 **Deploy to GitHub Pages**，点击 **Run workflow**。后续提交到 `main` 会自动部署。
6. 等待工作流完成后，在 Settings → Pages 中打开网站地址。通常格式为 `https://你的用户名.github.io/仓库名/`。

如果网页上传时遗漏隐藏的 `.github` 文件夹，可在 GitHub 点击 **Add file → Create new file**，文件名填 `.github/workflows/pages.yml`，把交付包中同名文件的内容复制进去再提交。

也可使用分支发布：不上传或删除 `.github/workflows/pages.yml`，在 Pages 中选择 **Deploy from a branch → main → /(root)** 并保存。本站不需要编译。

部署设置参考：[GitHub 官方 Pages 发布源说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。

## 功能

- 四门课程各自显示来源说明和投稿邮箱 `barcazqn@gmail.com`。
- 顺序练习、随机练习、背题模式、错题复习、收藏练习。
- 单选、多选、判断题；多选必须完整选中正确选项才通过。
- 章节、题型筛选；搜索题干与选项；答题卡跳转；键盘操作。
- 模拟测试随机抽取至多 30 题，限时 30 分钟；选择即保存，可随时修改；到时自动交卷。
- 测试结束逐题核对，保存最近测试成绩；未作答题按错误计。
- 每门课程的六种模式分别保留练习或测试位置；刷新或关闭页面后可继续。
- 作答统计、错题本、收藏、本机进度自动保存；答对后从错题本移出。
- 记录导出/导入；清空记录需确认；深色模式；手机与电脑布局。
- 党史题目附原扫描件页码与核对链接。

## 连续刷题操作改进

- 练习页占据完整屏幕，底部的上一题与下一题保持固定位置。题干、选项和核对结果在题目区域内滚动，切题只回到新题题干，不再把整页拉到顶部。
- 普通练习的单选与判断默认选择后立即核对，可关闭“选后核对”；不自动跳题，留出看答案的时间。多选需选齐后点击“核对答案”，再按同一位置的“下一题”继续。
- 尚未选择时，下一题显示为“跳过本题”。选了但尚未核对时，该位置显示“核对答案”，防止草稿被无意当作已完成。
- 模拟测试选择即保存；修改、取消多选也立即保存。刷新、返回课程后可继续。时间到、重新回到页面和继续答题前都会检查截止时间；交卷仅计分一次。
- 各模式单独保存进度。首页可直接续练；课程内显示该模式的题组与位置，继续练习不受新筛选条件影响。旧版本的进度和备份会自动兼容。
- 章节、题型、搜索和上次选择的模式会被记住；可只练从未作答的题，也可一键重置筛选。空题组显示相应处理提示。
- 手机答题卡可收起，跳题后自动关闭；可以定位下一道未答题。练习结果可补完未答题或再练本轮错题；测试结果可只看错题，或转入错题练习。
- 数字 1–8 选择；Enter 核对或继续；左右方向键切题。快捷键不会干扰输入框，也可在点击选项后继续使用。

## 本机保存的范围

记录使用浏览器 `localStorage`，按照网站地址、浏览器和设备隔离保存，不上传到服务器。手机和电脑不会自动同步；需要手动导出备份，再在另一台设备导入。导入会替换当前记录。换域名、从预览切换到 GitHub 地址、换浏览器、清除网站数据或使用无痕模式，可能使原记录无法访问。

练习统计中的“正确”以题库参考作答判定。背题模式不计入练习统计；模拟测试在交卷时一次性计入。测试计时使用绝对截止时间，关闭页面后时间仍继续。每门课程的六种模式分别保存进度，重新开始同一模式需确认替换；历史答题与收藏仍保留。

多个标签页同时打开时，另一个标签页更新记录后，当前页面会提示刷新，防止覆盖记录。

## 本地预览

不要直接双击 HTML（浏览器可能阻止题库加载）。在这个文件夹打开终端，运行：

```sh
python3 -m http.server 8000
```

再访问 `http://localhost:8000`。

## 修改与追加题目

编辑 `data/party.json`、`data/china.json`、`data/reform.json` 或 `data/communication.json`，每道题格式如下：

```json
{
  "id": "reform-new-001",
  "chapter": "1.1 改革是社会主义发展的内在要求",
  "type": "single",
  "stem": "题干内容（ ）。",
  "options": {"A": "选项一", "B": "选项二", "C": "选项三", "D": "选项四"},
  "answer": ["B"]
}
```

`type` 支持 `single`（单选）、`multiple`（多选）、`judge`（判断）。判断题使用 A 正确、B 错误；多选答案如 `["A", "C"]`。可加 `note` 记录整理说明，党史可加 `sourcePage` 对应原 PDF 页码。

每道题 `id` 应全局唯一，且以该课程 ID 加 `-` 开头。纠正题目文字时请保留现有 ID，避免丢失已有记录；如果更换了题目含义或答案，建议设置新 ID，避免把旧作答当成新题记录。修改题库后提交到 GitHub 即可更新网站。

## 文件结构

- `index.html`：页面入口。
- `style.css`：响应式布局、配色和深色模式。
- `app.js`：课程、答题、筛选、测试和记录界面。
- `engine.js`：判分、作答记录与备份校验。
- `data/`：四门课程 JSON 题库。
- `sources/party.pdf`：党史原扫描件，仅用于核对原题。
- `sources/communication.docx`：有效沟通技巧原始章节测试文档。
- `.github/workflows/pages.yml`：GitHub Pages 自动部署。
- `tests/validate.cjs`：题库结构、判分和备份校验测试，运行 `node tests/validate.cjs`。
- `tests/workflow.cjs`：连续答题、测试自动保存、模式隔离、旧备份升级与计时边界测试，运行 `node tests/workflow.cjs`。
